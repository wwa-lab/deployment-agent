## 本地 dev 环境联调
- 用户发现后端未启动；排查后发现两个原因：
  1. 环境注入 `SERVER__PORT=51931`，导致第一次 `mvn spring-boot:run -Plocal` 随机绑定到 51931。
  2. `frontend/vite.config.ts` 中 proxy target 是 `localhost:8080`，与 local profile 的 `server.port=8081` 不一致。
- 已修复：
  - 启动后端时显式覆盖：`SERVER__PORT=8081 mvn spring-boot:run -Dspring-boot.run.profiles=local -Dspring-boot.run.arguments="--server.port=8081"`
  - 将 `vite.config.ts` 的 `/api` proxy target 改为 `http://localhost:8081`
  - 重起 frontend dev server
- 验证：POST /api/platform/auth/login 直接和后端都返回 200，proxy 通过。

## 长驻 dev 服务启动方式（重要教训）
- 用 Bash 工具的 `run_in_background` 启动 Spring Boot / Vite 长驻进程，会在一段时间后（或 agent turn 结束）被回收，导致用户端"服务没起来"。
- **正确做法**：用 `nohup ... > /tmp/xxx.log 2>&1 &` 脱离终端启动，再轮询端口验证。本次后端 pid 在 8081 正常监听、前端 5173 正常、proxy 通过。
- 轮询后端就绪时别用 `GET` 那些只接受 POST 的接口（如 `/api/platform/auth/login`），会被 Spring Security 返回 405 并刷一堆 `HttpRequestMethodNotSupportedException` 噪音日志，误判为故障。用 `POST` 或查 `/actuator/health`（若启用）。
- 判断后端是否真起：看日志 `Tomcat started on port 8081` + `lsof -i :8081`。
