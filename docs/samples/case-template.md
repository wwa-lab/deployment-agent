# 案例记录模板

复制到新的案例/版本位置填写，保留此模板。不能在未获授权时补入真实姓名、Staff ID、客户数据、内部端点或凭据。

| 字段 | 填写内容 |
|---|---|
| 案例 ID / 版本 | |
| 类型 | 合成说明 / 合成自动化测试 / 获授权脱敏真实实践（三者选一） |
| 来源与原始位置 | |
| 来源 commit / 工具版本 | |
| 原始采集时间 / 本次记录时间 | |
| 授权范围与记录引用 | 真实实践必填；公开文本不列个人信息 |
| 脱敏方法与复核结论 | |
| 使用者角色与工作场景 | 不填个人身份 |
| 基线处理方式及成本 | 未测量则明确填写“未测量” |
| 输入文件 / 版本 / SHA-256 | |
| 输出文件 / 版本 / SHA-256 | |
| 环境与执行入口 | 合成环境或获批准的环境分类，不放真实内部端点 |
| 验证命令及断言 | 分开写静态检查、编译、模拟测试、真实运行、业务验收 |
| 原始 stdout / stderr / 报告位置与 SHA-256 | 保留原文；不可公开则引用获授权归档，不粘贴原文 |
| 人工介入 | 输入准备、参数修正、操作、审批、失败处理；次数与分钟未测则写未知 |
| 运行结果 | 成功、失败、部分完成或未执行；保留所有尝试 |
| 可证明的结论 | |
| 不能证明的结论 | |
| 指标分母、样本数及对照 | 未测则留空并明确“无实测收益” |
| 与上一版本关系 | 新运行 / 修正；写清变动，不覆盖旧版 |
| 后续行动 | |

结果分四层写：已实现能力；本案例验证到的范围；尚未验证效果；下一步测量。跳过、失败和人工兜底必须保留，不能只选择成功输出。

SHA-256 校验示例（填写真实的新文件路径后运行）：

```bash
shasum -a 256 path/to/artifact
```

Windows PowerShell：

```powershell
Get-FileHash -Algorithm SHA256 path/to/artifact
```
